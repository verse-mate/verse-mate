# Runbook — fill the missing line-by-line explanations

Makes sure every verse the Jesus feature prints carries a By-Line explanation.
Run the check whenever a reader reports an empty By-Line tab, and after any
batch that generates chapter bylines.

## Why the gap exists at all

The Jesus screens generate no By-Line content of their own, and don't need to.
The commentary stored per Bible chapter is keyed by (book, chapter, verse) and
an event knows the verses it spans, so the client narrows the chapter's byline
down to the pericope. That is only ever as complete as the chapters behind it,
and there are two ways it comes up short:

| | what the reader sees | fill |
| --- | --- | --- |
| **ungenerated** — the chapter has no active byline | the passage with nothing under it | generate that chapter |
| **partial** — the chapter has a byline that skipped some of the event's verses | some verses explained, others not | regenerate that chapter |

They look identical on screen and are counted separately, because only the
second one is invisible to "has this chapter been generated?".

A third gap was in the client rather than the content: the tab used to fetch the
primary account's chapter only, so on an event several Gospels tell — Matthew
4:17 and Mark 1:14-15 for "Repent, for the kingdom of heaven is at hand" — the
other accounts showed nothing however well generated their chapters were. Fixed
in the web client; if a passage still shows nothing, this runbook is the reason.

## 1. Check

```sh
cd packages/backend-base
bun run jesus:byline              # the whole corpus
bun run jesus:byline -- --gaps    # only the passages with gaps
bun run jesus:byline -- --json    # for CI, or to drive a fill
bun run jesus:byline -- --strict  # exit 1 when anything is missing
```

It reads and never writes. The report ends with the chapters to generate,
grouped by book — that list is the input to step 2.

## 2. Fill

Chapter bylines are generated by the admin batch operation, not by this script:
one submission at half price with a 24h window, which is what a run of a few
hundred chapters wants. In the admin batch UI, submit a **book batch** per book
the report named, with:

- **type**: `byline` only
- **chapters**: the numbers the report printed for that book
- **skip existing**: *off* for the `partial` chapters — the whole point is to
  replace a byline that skipped verses. Leave it on if you are only filling
  `ungenerated` ones.

Regenerating is what fills a partial chapter. There is no per-verse top-up: the
byline is one document per chapter.

## 3. Confirm

```sh
bun run jesus:byline -- --strict
```

Zero verses missing is the finish line. A chapter that comes back partial twice
is a generation problem, not a coverage one — `findVersesMissingSummary` names
the verses, and the chunked byline path in `shared/byline-chunking.ts` is where
a chapter long enough to lose its tail gets split.
